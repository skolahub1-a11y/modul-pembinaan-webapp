Modul latihan guru · 6 modul · 90 minit

Bina web app sekolah sendiri.
Tanpa pelayan, tanpa kos.

Satu modul lengkap: Gemini Canvas untuk frontend, Google Apps Script sebagai backend, Google Sheets sebagai database, dan hosting percuma. Untuk guru yang mahu sistem sendiri — borang kehadiran, kuiz, senarai murid, rekod bantuan — dan tak mahu bergantung pada kertas atau WhatsApp.

Kenapa

Masalah biasa di sekolah, dan jalan keluarnya

Kebanyakan masalah urusan sekolah ialah masalah data — siapa hadir, siapa belum bayar, siapa dapat markah berapa. Fail Excel di komputer peribadi dan borang kertas tidak boleh dikongsi atau dianalisis.

Cara lama

  • Borang diedar, diisi tangan, then ditaip semula ke Excel — kerja berganda.
  • Fail Excel dalam telefon peribadi, versi berbeza setiap guru.
  • Kutipan bayaran/kehadiran sukar dijejaki; guru besar minta laporan, kena kira manual.
  • Penyelesaian berbayar (Google Forms terhad, sistem komersial) mahal atau tak fleksibel.

Cara baru (modul ini)

  • Guru isi web app dari telefon; data terus masuk ke satu Sheet.
  • Semua guru lihat data sama, versi sama, masa nyata.
  • Laporan = satu paparan/grafik yang dikira sendiri oleh app.
  • Kos: RM0. Kemahiran: cukup untuk diselenggara sendiri, tanpa pelayan.
Prinsip modul ini: satu perubahan kecil pada satu masa. Setiap modul boleh diuji sendiri — kalau satu bahagian gagal, yang lain tetap jalan.
Peta besar

Empat bahagian sesebuah web app

Setiap web app ada empat bahagian. Faham peranan setiap satu, dan seluruh modul ini jadi mudah — termasuk bila nak tukar database atau hosting.

Frontend = kaunter restoran

Bahagian yang dilihat dan disentuh oleh guru: borang, butang, jadual, grafik. Ia tidak menyimpan apa-apa dan tidak boleh menyimpan rahsia — kodnya boleh dilihat sesiapa melalui “View Source”.

  • Alat: Gemini Canvas (satu prompt), apa-apa editor teks, VS Code, Notepad.
  • Fail: satu fail index.html (HTML + CSS + JS sekali).
  • Peraturan besi: API key, kata laluan, token — tidak sekali-kali di sini.

Backend = dapur

Dapur menerima pesanan, menyemak bahan, memasak, kemudian menghantar hasil. Di sini juga resepi rahsia (API key) disimpan — pelanggan tak nampak.

  • Alat: Google Apps Script (percuma, duduk dalam Sheet yang sama). Tanpa pelayan, tanpa bayaran.
  • Fail: Code.gs — fungsi doGet() (baca) dan doPost() (tulis).
  • Peranan: sahkan input, elak data sampah, simpan rahsia, kawal siapa boleh baca/tulis.

Database = gudang

Tempat data disimpan secara kekal. Google Sheets cukup untuk kebanyakan urusan sekolah, tetapi ada had — Modul 4 menerangkan bila patut pindah ke Supabase, Firebase, MongoDB atau MariaDB.

  • Mudah & percuma: Google Sheets (10 juta sel setiap fail).
  • Bila data mula besar/ramai pengguna: Supabase (Postgres), Firebase, MongoDB Atlas, MariaDB/MySQL.
  • Amalan wajib: backup mingguan (Sheet → Download → .xlsx) dan siapkan header yang tetap.

Hosting = dewan makan

Supaya orang lain dapat masuk. Semua pilihan dalam modul ini percuma — beza utama ialah berapa mudah dikemas kini.

  • Google Sites — embed URL /exec, paling mudah, sesuai untuk guru.
  • Cloudflare Pages / Netlify — drag & drop fail, URL cantik, domain sendiri boleh.
  • GitHub Pages — percuma, sesuai bila anda mahu kawalan versi (site ini sendiri diletak di sini).
Modul 1

Frontend dengan Gemini Canvas

Canvas ialah bengkel: satu prompt, dua hasil — fail index.html (frontend) dan Code.gs (backend). Ia bukan database dan bukan host.

Apa yang bagus

  • Satu prompt → reka bentuk + kod + backend sekali.
  • Boleh minta perubahan bahasa Melayu, warna, susun atur.
  • Jimat masa untuk guru yang bukan pengaturcara.

Hadnya

  • Bukan database, bukan hosting, bukan jaminan kod betul sepenuhnya.
  • Kod mesti diuji — baca, faham, betulkan sendiri.
  • Jangan letak kunci API di frontend walau apa pun yang Canvas cadang.

Hasil

  • index.html — simpan dalam folder projek.
  • Code.gs — akan tampal ke Apps Script (Modul 2).
  • Satu penanda: PASTE_URL_APPS_SCRIPT_DI_SINI.

Prompt Canvas yang boleh terus guna

Tampal dalam Gemini Canvas. Perhatikan bahagian FRONTEND dan BACKEND — kedua-duanya diminta dalam satu prompt.

prompt-canvas.txt
Bina satu webapp responsif dalam SATU fail index.html tanpa library luar,
DAN sediakan kod Code.gs untuk Google Apps Script (backend).

Bahasa antaramuka: Bahasa Melayu.

FRONTEND (index.html):
1. Borang dengan medan nama dan mesej.
2. Butang Simpan menghantar POST ke Google Apps Script.
3. Butang Baca Data membuat GET dan memaparkan rekod dalam jadual.
4. Paparkan loading, berjaya, ralat dan empty state.
5. Mesra telefon dan mudah digunakan oleh guru.

Gunakan:
var GAS_URL = 'PASTE_URL_APPS_SCRIPT_DI_SINI';

Untuk POST:
fetch(GAS_URL, { method: 'POST', body: JSON.stringify(data) });
Jangan tetapkan Content-Type: application/json untuk pola GAS ini.

BACKEND (Code.gs) — sedia untuk tampal dalam Extensions → Apps Script:
- var SHEET_NAME = 'Log'
- doGet() baca data dan balas JSON
- doPost(e) semak body.nama dan body.mesej, tulis row guna LockService
- getSheet_() cipta tab Log jika belum ada (header: masa, nama, mesej)
- json_(data) balas ContentService JSON
Kenapa tiada header Content-Type: application/json? Ia mencetuskan preflight (OPTIONS) yang Apps Script tolak dengan 403. Hantar JSON sebagai body biasa sahaja — ini punca nombor satu “kenapa simpan tak jalan”.
Modul 2

Backend: Google Apps Script

Backend ialah tempat data disemak dan disimpan, dan tempat rahsia (API key) dilindungi. Anda tidak memasang apa-apa pelayan — semuanya di Google.

Buka Sheet, bukan editor berasingan

Dalam Google Sheet: Extensions → Apps Script. Padam kod contoh, tampal Code.gs dari Canvas.

Extensions

Deploy sebagai Web app

Deploy → New deployment → Web app. Execute as: Me. Who has access: pilih ikut sensitiviti data (untuk ujian: Anyone; untuk data murid: hanya akaun sekolah).

Penting

Salin URL yang berakhir /exec

Bukan URL editor, bukan /dev. URL ini yang dihubungkan ke frontend.

/exec

Selepas setiap perubahan kod: versi baharu

Deploy → Manage deployments → Edit → Version: New version → Deploy. URL kekal sama — ini sebab “kod dah ubah tapi masih sama”.

New version

Code.gs — backend minimum yang lengkap

Code.gs
var SHEET_NAME = 'Log';

function doGet(e) {                       // BACA:  fetch(GAS_URL + '?action=read')
  var sh = getSheet_();
  return json_(sh.getDataRange().getValues());
}

function doPost(e) {                      // TULIS: frontend POST JSON
  try {
    var body = JSON.parse(e.postData.contents);
    if (!body.nama || !body.mesej) return json_({ ok: false, ralat: 'Medan wajib kosong' });

    var lock = LockService.getScriptLock();   // elak dua tulisan serentak
    lock.waitLock(20000);
    try {
      getSheet_().appendRow([new Date(), body.nama, String(body.mesej).slice(0, 500)]);
    } finally {
      lock.releaseLock();
    }
    return json_({ ok: true });
  } catch (err) {
    return json_({ ok: false, ralat: String(err) });
  }
}

function getSheet_() {                   // cipta tab + header jika belum ada
  var ss = SpreadsheetApp.getActiveSpreadsheet();
  var sh = ss.getSheetByName(SHEET_NAME);
  if (!sh) {
    sh = ss.insertSheet(SHEET_NAME);
    sh.appendRow(['masa', 'nama', 'mesej']);
  }
  return sh;
}

function json_(obj) {                    // WAJIB untuk web app
  return ContentService.createTextOutput(JSON.stringify(obj))
    .setMimeType(ContentService.MimeType.JSON);
}
Had percuma: ~20,000 permintaan/hari dan 6 minit setiap pelaksanaan. Untuk borang kehadiran, kuiz dan rekod sekolah — jauh lebih daripada cukup.
Jangan: letak API key, nombor telefon guru atau kata laluan di dalam frontend. Semua rahsia duduk dalam Project Settings → Script Properties, dan dipanggil oleh backend.
Modul 3

Database: Google Sheets

Sheet ialah gudang yang boleh anda buka, semak dan edit sendiri — inilah kelebihan besarnya berbanding database “sebenar” untuk kegunaan sekolah.

Susunan yang betul

  • Baris 1 = header tetap: masa | nama | kelas | … Jangan tukar nama header selepas sistem hidup.
  • Satu jadual = satu tab. Jangan campur rekod kehadiran dengan rekod bayaran.
  • ID unik (cth nombor kad pengenalan atau nombor pendaftaran) untuk elak rekod berganda.
  • Tarikh simpan sebagai tarikh sebenar, bukan teks — supaya boleh ditapis dan dijumlah.
  • Jangan simpan data sensitif (perubatan, disiplin, gaji) dalam Sheet yang dikongsi awam.

Had & amaran

  • Had ~10 juta sel setiap fail. Ratusan ribu baris masih OK; jutaan — tidak.
  • Bilangan pengguna serentak yang tinggi boleh lembap (Sheet bukan database web sebenar).
  • Sheet boleh dipadam oleh sesiapa yang ada akses — backup mingguan wajib.
  • Bila data makin besar → pindah ke Supabase/Firebase/MongoDB/MariaDB (Modul 4).

Contoh permintaan & jawapan (yang anda patut uji sendiri)

uji-frontend.js
var GAS_URL = 'https://script.google.com/macros/s/AKfycb…/exec';

// 1) TULIS — tiada header Content-Type (elak preflight 403)
fetch(GAS_URL, {
  method: 'POST',
  body: JSON.stringify({ nama: 'Cikgu Amin', mesej: 'Ujian pertama' })
}).then(function (r) { return r.json(); }).then(console.log);

// 2) BACA
fetch(GAS_URL + '?action=read')
  .then(function (r) { return r.json(); })
  .then(function (rows) { console.log(rows.length + ' rekod'); });

// Ujian lulus apabila: borang → baris baharu muncul dalam tab Log → Baca Data
// memaparkan baris yang SAMA, dan loading / ralat / empty state turut kelihatan.
Modul 4

Bila Sheet tak cukup: Supabase, Firebase, MongoDB, MariaDB

Sheet mengalah bila data jadi besar, pengguna ramai, atau bila anda perlukan login pengguna dan kebenaran yang ketat. Ini pilihan yang biasa digunakan guru-guru dan sekolah — semua ada peringkat percuma.

PilihanJenisKos asasPaling sesuai untukPerhatian
Google SheetsHamparan (spreadsheet)Percuma Borang, kehadiran, kuiz, rekod ringan; data boleh dilihat & diedit terus Had sel & pengguna serentak; bukan untuk data sensitif awam
SupabasePostgres + auth + storagePercuma (2 projek) App dengan login Google, peranan pengguna, data berstruktur & berhubung Perlu faham sedikit SQL; boleh self-host jika sekolah ada pelayan
FirebaseDokumen (Firestore) + authPercuma (Spark) App masa nyata (kehadiran langsung), mudah untuk pemula, login Google Pertanyaan terhad berbanding SQL; keluar dari rangka kerja Google susah sedikit
MongoDB AtlasDokumen (NoSQL)Percuma (512 MB) Data tidak seragam/berubah bentuk, log, data mentah Perlu backend sendiri (Node/Apps Script tak sesuai); tak ada hubungan jadual
MariaDB / MySQLSQL klasikPercuma (self-host) Sistem lama sekolah (PHP), laporan berat, kawalan penuh Mesti ada pelayan (komputer/NAS/rumah); perlu buat backup sendiri

Cara memilih (soalan 3 detik)

  • Data perlu dilihat/diedit guru terus? → Google Sheets.
  • Perlu login & peranan (guru/admin/murid)? → Supabase atau Firebase.
  • Data tak seragam, cuma simpan & baca? → MongoDB.
  • Sekolah dah ada pelayan & sistem PHP? → MariaDB/MySQL.

Amalan sama walau apa database

  • Frontend tidak pernah menyimpan kunci database yang boleh menulis tanpa had.
  • Semakan hak akses di server (Apps Script / Edge Function / API), bukan di frontend.
  • Backup berjadual + ujian pulih (restore) sekali sekala.
  • Nama medan & struktur diasingkan supaya boleh tukar database tanpa tulis semula frontend.
Tip untuk sekolah dengan NAS/pelayan sendiri: Supabase boleh dipasang sendiri (self-host) — data tinggal dalam sekolah, tiada kos langganan, dan login boleh guna akaun Google sekolah. Pilihan ini sesuai bila data melibatkan murid.
Modul 5

Hosting percuma: Google Sites, Cloudflare Pages, Netlify, GitHub Pages

Frontend anda satu fail index.html. Tugas hosting cuma meletakkan fail itu di tempat yang boleh dibuka orang lain.

PilihanBagaimanaSesuai bilaPerhatian
Google Sites
Percuma		 Insert → Embed → By URL → tampal URL /exec → Publish Paling mudah untuk guru; semua dalam ekosistem Google Embed sahaja — susun atur terhad; sesuai untuk app satu halaman
Cloudflare Pages
Percuma		 Drag & drop folder, atau hubungkan repo GitHub Mahu URL cantik + domain sekolah sendiri + laju (CDN) Perlu akaun Cloudflare; domain sendiri perlu pendaftaran berbayar
Netlify
Percuma		 Drag & drop folder ke app.netlify.com/drop Nak hidupkan URL dalam 30 saat tanpa daftar rumit Nama URL rawak (boleh tukar); had jalur lebar peringkat percuma
GitHub Pages
Percuma		 Repo awam → Settings → Pages → branch main Mahu simpan versi (sejarah perubahan) & kemas kini berulang Perlu tahu sedikit git; repo mesti awam untuk peringkat percuma

Langkah GitHub Pages (4 langkah)

  • Cipta repo awam, contoh webapp-kehadiran.
  • Muat naik index.html (dan apa-apa fail sokongan).
  • Settings → Pages → Source: Deploy from a branch → main → / (root) → Save.
  • Tunggu 1–2 minit → buka https://<nama-akaun>.github.io/webapp-kehadiran/.

Website ini pun bukti

  • Modul ini sendiri diletak di GitHub Pages — percuma, awam, boleh dikemas kini.
  • Frontend sahaja: tiada pelayan, tiada pangkalan data untuk modul ini.
  • Boleh juga disimpan sebagai fail dan dibuka terus tanpa internet — sesuai bila venue tiada Wi-Fi.
Perhatian penting: URL Apps Script (/exec) yang dibenarkan “Anyone” bermaksud sesiapa yang tahu URL boleh hantar data. Untuk data murid, pilih akses terhad (akaun sekolah) dan sahkan pengguna di backend.
Modul 6

Keselamatan & amalan baik

Enam peraturan ini membezakan app “boleh guna” dengan app “boleh dipecahkan orang”.

Rahsia di server

API key, token, kata laluan → Script Properties / pemboleh ubah persekitaran di backend. Frontend hanya menyebut nama tindakan, bukan kunci.

Semak di server

Jangan percaya apa yang datang dari frontend. Sahkan medan wajib, had panjang teks, format emel/kad pengenalan di backend.

Login & peranan

Untuk data murid: guna login akaun sekolah (Google SSO) dan tetapkan siapa admin, siapa guru, siapa hanya baca.

Backup berjadual

Sheet → File → Download (.xlsx) setiap minggu; atau skrip salinan automatik. Backup yang tidak pernah diuji bukan backup.

Jejak siapa ubah apa

Tambah medan emel_pengguna + masa pada setiap tulisan. Bila ada salah faham, rekod menjawab.

Data peribadi murid

Kumpul yang perlu sahaja. Jangan kongsi Sheet kepada “anyone with the link”; jangan simpan nombor kad, kesihatan atau gaji dalam app percubaan.

Idea app untuk sekolah

  • Borang kehadiran program (dengan masa masuk/keluar).
  • Kuiz ringkas + markah automatik.
  • Senarai murid & rekod bayaran PIBG.
  • Tempahan bilik/aset (projektor, gelanggang).
  • Borang aduan & maklum balas ibu bapa.

Naik taraf seterusnya

  • Tambah eksport PDF untuk laporan bulanan.

Bila tak menjadi

Masalah biasa dan penyelesaiannya

Simpan gagal / ralat 403
Anda kemungkinan menetapkan Content-Type: application/json pada panggilan POST. Buang header itu — hantar body: JSON.stringify(data) sahaja. Semak juga access deployment (Anyone atau akaun sekolah).
Kod sudah diubah, tetapi app masih berkelakuan lama
Apps Script menjalankan versi deployment, bukan kod terbaru secara automatik. Pergi ke Manage deployments → Edit → Version: New version → Deploy. URL tidak berubah.
Data tidak muncul walaupun tiada ralat
Semak nama tab (SHEET_NAME) dan baris header. Jika header ditukar selepas sistem hidup, bacaan mengikut lajur boleh tersasar. Gunakan butang Baca Data untuk membandingkan dengan apa yang dilihat dalam Sheet.
App berhenti seketika (quota)
Had Apps Script ialah ~20,000 permintaan/hari dan 6 minit setiap pelaksanaan. Untuk puncak yang jarang, had ini cukup; jika selalu terkena, pecahkan operasi kepada beberapa permintaan kecil, atau pindah logik berat ke database sebenar.
Sheet menjadi sangat besar / lambat
Bila melebihi beberapa ratus ribu baris atau pengguna serentak ramai, pindah ke Supabase/Firebase (Modul 4). Struktur medan yang kemas menjadikan penghijrahan ini jauh lebih mudah.
Fail tidak berubah apabila dikemas kini
Ini selalunya cache pelayar. Tekan Ctrl+Shift+R (Windows) atau Cmd+Shift+R (Mac), atau buka dalam tetingkap incognito. Untuk hosting sendiri, pastikan server tidak menyimpan versi lama.
Soalan lazim

Soalan yang selalu ditanya guru

Saya tak tahu coding. Boleh ke?
Boleh. Peranan anda ialah menyatakan keperluan dengan jelas dan menguji hasilnya. Canvas menulis kod; anda menyemak sama ada borang, jadual dan mesej ralat berkelakuan betul. Mulakan dengan satu app kecil.
Betul ke percuma sepenuhnya?
Ya untuk pakej modul ini: Canvas (peringkat percuma), Apps Script, Sheets, dan hosting (Google Sites / Cloudflare Pages / Netlify / GitHub Pages). Kos tersembunyi biasanya hanya domain sendiri (pilihan) atau had peringkat percuma bila trafik sangat tinggi.
Data murid selamat tak?
Ia bergantung sepenuhnya pada cara anda mengawal akses: siapa boleh buka URL, siapa boleh tulis, dan sama ada data itu diletakkan di tempat yang betul. Untuk data sensitif: hadkan akses kepada akaun sekolah, sahkan pengguna di backend, dan jangan sesekali letak kunci di frontend.
Bila patut tinggalkan Google Sheets?
Tiga tanda: (1) data melebihi had sel atau menjadi lambat, (2) perlukan login & peranan berbeza, (3) perlu hubungan antara beberapa jadual (cth murid ↔ kelas ↔ markah). Ketiga-tiganya menunjuk ke Supabase/Firebase.
Boleh guna untuk sistem lama sekolah (PHP/MySQL)?
Boleh, tetapi ia jalan cerita berbeza: PHP + MariaDB memerlukan pelayan dan penyelenggaraan sendiri. Gunakannya bila sistem sedia ada sudah wujud dan anda hanya menambah fungsi — bukan untuk memulakan projek baharu.
Bagaimana mahu mula mengajar guru lain?
Guna mod bentang dalam laman ini untuk sesi 30–45 minit: peta besar dahulu, kemudian tunjuk satu aliran lengkap (borang → Sheet → baca semula), dan akhiri dengan amali 30 minit. Satu app berjaya lebih berkesan daripada sepuluh konsep.
Penutup

Satu app kecil hari ini lebih berguna daripada rancangan besar tahun depan

Modul ini direka untuk guru: tanpa pelayan, tanpa kos, dan boleh diselenggara sendiri. Mula dengan satu masalah sebenar di sekolah anda — borang, kehadiran, atau kuiz — dan selesaikan sepenuhnya sebelum menambah fitur.
